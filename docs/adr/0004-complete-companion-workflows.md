# 0004: Division follows, source operations and reviewed registration exports

Date: 2026-10-17. Status: proposed in this PR. Compatible with ADRs 0001–0003.

- Guest follows remain local. Division IDs are stored separately from entry IDs in the same version-compatible list; the server expands current division membership. My Day keeps individually followed teams first and lazy-loads followed divisions in collapsible sections (R-03). Private labels have a separate local key and are never sent to the API (R-32/R-35).
- The companion displays source rounds and placeholders. It never seeds, advances, reschedules or scores a competition. Match references preserve the source identity (ADR 0002).
- AES reads the event, timestamp, playdays, pools and poolsheets through a bounded transport. Four poolsheet requests may run concurrently. An unchanged source timestamp avoids reimporting. Unsupported payloads are rejected. Actual AES validation from this environment is blocked by the upstream WAF (HTTP 403); contract tests use representative payloads, not a captured AES response. A live run against OVA's selected event is still required.
- TIMU has a separate HTML adapter verified against the published results for event 3960: nine entries and 21 match cards. Results cards do not reliably contain scheduled start times, so those remain unknown. Staff can import an approved schedule CSV into the same source. Official scoresheets, scoring guide and submission links are extracted as guide resources.
- Source checks run centrally in the API lifespan. A PostgreSQL advisory lock serializes refreshes across replicas. Automatic checks are opt-in per source; paused sources are skipped. Source errors retain the last published schedule. CSV fallback remains available for every source and is labelled as an imported snapshot.
- MRS is not assumed to have a documented CSV schema or API. Staff map an existing registration export's selected public columns and exact registration team IDs to event entries. The mapped import creates drafts. An event/entry-scoped coach must approve the exact draft version before staff can publish it with a consent-review reference. Corrections use a new import/version; withdrawn versions cannot be republished. Original eligibility/contact fields are not imported by this workflow.
- Officials receive private assignments through audited staff create/edit/delete operations or validated CSV preview/commit. Official role grants must already exist. The public change feed never includes assignment subjects.
- Court areas are configured by staff. A delay notice adds an explicitly attributed estimate to an unchanged official start, expires automatically, can be cleared early and can apply to an area. A later official-time revision supersedes that estimate without removing the explanatory notice. Work teams supplied by the source are distinct from match participants and personal officials.
- The demo clock is available only for events explicitly marked as demos. It ticks forward from a staff-set anchor, is visible to attendees and supports +15-minute jumps. It changes presentation and notice validity; it never manufactures source results or advances placeholders.
- Large lists use incremental loading with stable record identities; updates use a before cursor. Accessibility uses native buttons/disclosures, labelled controls, focus visibility and non-colour status descriptions. Automated axe checks complement, and do not replace, a manual screen-reader/zoom review.

No attendee accounts, separate worker service, private bucket, mail provider, payment service or new hosting environment variables are introduced.
